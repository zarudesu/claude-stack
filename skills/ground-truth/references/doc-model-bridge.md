# Канонические знания для агентов

Это обязательная часть init, а не опциональная документация для людей.
Отдельно установленный doc-model не нужен: ниже минимальный самостоятельный
процесс. Если он есть и вызван, передать готовый инвентарь и результаты
исследования; не заказывать второй полный discovery.

## Одно знание — один дом

- L0: короткий вход в проект с командой получения контекста, расположением модели,
  границами и общими ограничениями. Не полный справочник.
- L1: маленькие правила по области/пути для использования, изменений и проверок.
- L2: канонические документы областей: поведение, решения и причины, API/данные,
  связи, инварианты, типовые пути изменения, команды проверок, известное неизвестное.
- L3: производные индексы, маршруты и task packets. Они ссылаются на L2 и источники;
  не становятся второй редактируемой копией истины.

Сначала сопоставить код, тесты и требования, затем укладывать подтверждённое знание.
Зелёный verifier сам по себе не устанавливает истинность всей прозы.
STATUS — индекс доказательств выбранных утверждений; rationale и карта изменения
не обязаны превращаться в YAML-claims. У каждого вида факта один канонический дом.

Использовать существующие правильные документы. Не создавать параллельный
справочник с теми же фактами. Большой документ при необходимости разложить по
областям с сохранением ссылок/требований; короткий контекст не достигается
потерей значимых исключений и ограничений.

## Сохранение смысла

Составить mapping старых нормативных утверждений: keep-inline / moved-to:path /
link / drop+причина. Покрыть все переносимые требования; независимым ревью
проверить критические полностью и репрезентативную выборку остальных.
Потерянное требование без решения = провал приёмки.

Не считать старое описание ненужным только потому, что его ещё нет в коде:
это может быть требование, открытое решение или долг. Не выносить полезный для
агента rationale в «человеческий архив» по формальному признаку.
Удаление, перенос и изменение внешних потребителей документа согласовать по
реальному запросу; не считать main-агента владельцем разрешения.
Не выполнять git add/mv/rm только ради синхронизации индекса без такого полномочия.
После разрешённого переноса исправить ссылки, модели и checks, проверить результат.

## Чувствительные данные

В документацию/пакеты не копировать секреты, production-данные и реальные
персональные случаи. Использовать обезличенные примеры. Watch по умолчанию
не читает gitignored файлы; canonical docs читаются явно, поэтому не указывать
в docs секретные файлы. Не отправлять исходники сторонним провайдерам без
разрешения. Найденные прежние утечки сообщить; массовая чистка истории/памяти
не разрешается этим скиллом.
