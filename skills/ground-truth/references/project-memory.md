# Исполняемая модель памяти

Python 3.10+, PyYAML, git. Исходник templates/gt_context.py; i9_install копирует
его в tools/ground_truth. Процесс построения/ревью — [init.md](init.md);
обычная дельта — [process.md](process.md). Runtime не вызывает модели, не
исполняет команды из docs/checks и не исправляет исходники.

## Артефакты и схема v1

- .ground-truth/model.yaml — области, источники и ориентированные зависимости.
- .ground-truth/review.json — content fingerprints и явные review receipts.
- .ground-truth/workspace — необязательный относительный путь к общему корню.
- Канонические документы — существующие или созданные по области файлы в repo.
  Шаблон: [context-model.yaml.template](../templates/context-model.yaml.template).

Model и receipts версионировать вместе с проектом; путь workspace переносимый.
Локальные task-worktree модели не должны перезаписывать canonical модель.
Не коммитить абсолютные личные пути. .ground-truth/review.json.lock — временный
lock записи, не knowledge; после аварии удалять только установив отсутствие
живого писателя. Не решать конфликт receipts выбором «самой поздней даты»:
пересмотреть изменённые области и сформировать подтверждение текущих входов.

repositories: непустой map с path относительно корня модели, watch (по умолчанию
весь "."), exclude: [{path, why}]. В path разрешён ../ для соседнего repo.
Каждый path — фактический git-root. Другой worktree того же git-common-dir не
новый сервис; выдача из неправильного зарегистрированного checkout запрещена.

areas: непустой список. Обязательны уникальные id, repo, summary, непустые sources
и docs. sources — repo-relative файлы/директории/шаблоны. docs — точные пути к
каноническим UTF-8 документам в этом repo. Не включать в sources четыре managed
пути: model.yaml, review.json, review.json.lock и workspace внутри .ground-truth/.
depends_on — IDs производителей, в том числе в других repo: consumer → producer.
entrypoints/checks/unknowns — списки строк. valid_until — необязательная
КАВЫЧЕННАЯ ISO-строка с timezone для внешнего свидетельства.
Неизвестные поля/ребра отклоняются, циклы обходятся с visited-set.

Точные пути/директории предпочтительнее glob. Шаблоны используют Python fnmatch,
не gitignore: "*" может совпасть с "/"; "." означает всё. Runtime рассматривает
git-tracked и nonignored untracked файлы. Hash включает байты и executable bit.
Удалённый источник, пустой source pattern, отсутствующий документ или repo —
ошибка. Symlink за границу repo не читается. docs читаются явно даже при ignore:
не указывать секретные документы.

Все наблюдаемые файлы должны входить в sources/docs какой-либо области.
Новый неклассифицированный файл — coverage gap, блокирует затронутый repo.
Генерируемые/сторонние данные исключать с причиной. Вне watch/ignore/зарегистрированных
repos нет гарантии обнаружения: полноту исходного scope проверяет init и аудит.
Новый игнорируемый сервис не будет магически обнаружен. Snapshot не проверяет
production, внешние настройки или смысл требований.

## Свежесть

Точный source-файл может явно включить безопасную ignored конфигурацию
(например, локальную настройку dispatch hooks). Он по-прежнему должен входить
в watch и не подпадать под exclude. Source-директории/globs игнорируемое дерево
не обходят. Не включать секреты/личные данные. Для различающихся окружений
вести локальную tooling-область/task-local receipts, иначе CI не совпадёт с
личными settings. Либо проверять согласованный безопасный effective contract
отдельным исполняемым probe. Простая копия описания без probe не обнаруживает
изменение фактической настройки.

Перенос checkout не меняет семантику при полностью совпадающих объявленных
байтах, scope и связях. Task-local копия модели может переназначить repo.path
на свой worktree и переиспользовать receipts идентичного содержимого.
Фактический checkout проверяется при выдаче; любое изменение его входов делает
знание stale. Полный workspace revision включает и пути, так что handoff явно
привязан к новой раскладке. Это не разрешает брать пакет из старого checkout.

Stamp области включает её определение, inputs и транзитивные зависимости.
Изменение кода, теста, docs, config или ребра требует смыслового пересмотра
затронутого знания. Receipt с другим stamp не актуален. Reviewed дата не
продлевает актуальность сама собой; expired valid_until нельзя «освежить»
без нового внешнего свидетельства и явного изменения metadata.

Hash-check подтверждает совпадение с рассмотренным содержимым, НЕ правильность
того рассмотрения. Реестр связей составляется исследованием; статический граф
не является доказательством полноты runtime-зависимостей. Обязательны независимая
первичная приёмка и риск-ориентированная повторная проверка.

## CLI

Запускать из рабочего repo: helper ищет model у предков или по workspace pointer.
--root ROOT ставится перед подкомандой; можно явно выбрать общий корень.

```sh
python3 tools/ground_truth/gt_context.py list
python3 tools/ground_truth/gt_context.py status --brief
python3 tools/ground_truth/gt_context.py context --area billing --area api
python3 tools/ground_truth/gt_context.py check
python3 tools/ground_truth/gt_context.py refresh --area billing --reviewed --expect REV --evidence "review details and actual checks"
```

list — дешёвая по выводу маршрутизация, не свидетельство готовности.
status/check: exit 0 готовые fingerprints всего реестра; 1 stale/gaps; 2
ошибка/нет модели. status выдаёт revision; подробности области — context repair.
Нет модели не равняется «нечего проверять». STATUS не заменяет model.
i9_install ставит helper, его CI-шаг и правило памяти только в repo, где discover
находит модель; без неё действует STATUS-only контракт (SKIP project memory).

context включает selected+transitive producers (документы), reverse consumers
(маршруты с их freshness), co_owned_areas (другие владельцы общих входов), unknowns
и checks. Общая проверка/конфигурация может затронуть несколько областей без
dependency edge; при её изменении рассмотреть всех владельцев, не только selected.
Документы co-owners не загружаются автоматически. Stale required area → нет доверенных
documents, exit 1. Отсутствующий независимый repo не запрещает другой свежий пакет,
но check всего workspace остаётся красным. Удалённые areas требуют явного ревью
и refresh --prune-removed, иначе глобальный результат не ready.

По умолчанию --max-chars 24000 — бюджет выдачи, НЕ токены. Документы не режутся
посередине: omitted_documents/packet_complete=false и exit 1. Уточнить область,
разделить канонический документ по смыслу или явно увеличить лимит; не принимать
неполный пакет за полный. Повторная проверка fingerprint защищает от изменений
во время выдачи; перед дальнейшим использованием старого пакета проверять снова.

refresh обновляет только выбранные receipts (либо --all). --expect связывает
подтверждение с наблюдённым revision; запись атомарна, конкурирующие записи
сериализованы lock. Источники не блокируются: последующее изменение делает
receipt stale. Никогда не вызывать refresh в hook или CI, не автоподставлять
«проверено» только потому, что status красный.

hook --event start: краткий статус, не запускает исследование.
hook --event stop: stale advisory предупреждает; blocking возвращает 2.
Ошибка checker/нет модели также nonzero. Внешний SessionStart не мешает начать
работу для ремонта. CI запускает check независимо от enforcement.
Stop зовёт hook только при грязном дереве и установленном helper; без модели
helper не ставится, и Stop/CI ведут себя как до появления памяти.

## Масштаб и стоимость

Вывод контекста ограничен задачей, но текущая реализация перечитывает hashes всех
наблюдаемых файлов (context проверяет snapshot повторно). Это затраты CPU/I/O,
не повторное чтение всего кода моделью. Для огромного workspace измерять время
и объём файлов до включения hook timeout; кэширование hashes не реализовано.
Нет обещания O(diff) по диску или доказанной токенной экономии.

Смысловой sync адресный; coarse sources/широкие зависимости могут сделать его
дорогим. Уточнять границы по фактам, не отключать propagation. При timeout
hook не доказал актуальность: PM/CI должны получить успешный check, а не
считать отсутствие вывода зелёным.
