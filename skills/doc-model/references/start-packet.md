# Стартовый пакет — контракт (фаза 7)

Derived-блок, который хук `SessionStart` вычисляет при старте сессии и кладёт в контекст модели до первого действия. Ничего не хранит, ничего не решает, статус не заменяет: канон остаётся там, куда указывает routing-таблица L0.

## Почему хук, а не текст и не обёртка

- Текст в L0 «прочитай README, проверь claims» — дисциплина. Новая сессия ещё ничего не читала, и правило срабатывает только если модель сама решит его выполнить.
- Печать из стартовой обёртки до `exec claude` уходит в терминал. Модель её не видит (замер 2026-09-22 на одном из проектов: doclint печатался из start.sh и в контекст не попадал).
- Вывод хука `SessionStart` платформа добавляет в контекст (`SessionStart hook success: …`). Без matcher хук срабатывает на `startup`, `resume` и `compact` — последнее важно: после сжатия контекст теряет claims и состояние, пакет возвращает их.

## Состав — четыре блока, порядок фиксирован

| # | Блок | Откуда | Форма |
|---|---|---|---|
| 1 | Свежесть документации | `doclint.py --root <root> --summary --tree` | 1 строка + по строке на вложенный репозиторий |
| 2 | Состояние портфеля | одна строка статуса/WIP из файла, который routing-таблица L0 называет домом статуса | счётчики, не пересказ; обрезать до ~200 символов |
| 3 | Кто где | claims-протокол репозитория (`session-claim.sh list` и аналоги); нет протокола — `git worktree list` | scope \| сессия \| режим \| дата \| цель; свежие сверху; primary-scope в таблицу, `file:`/`external:` — одной строкой по сессиям; лимит 10 строк + «…ещё N» |
| 4 | Маршрутизация действий | указатели на дома: cold-start-шаги L0, контракт движения задачи (claim → план → write-back → release/handoff), протокол claims | 1–3 строки, ни одного правила дословно |

Лимиты: ≤ ~40 строк, ≤ ~4 KB, ≤ 1 с. Дорогие проверки (doctor claims, сетевые запросы, чтение прода) в пакет не входят — их зовёт cold-start-шаг по необходимости.

## Чего в пакете нет

- Копий routing-таблицы и правил L0/L1: они уже в контексте, платформа грузит их сама. Только указатель «где».
- Derived-роутера задач (L3), если его инжектит другой хук — глобальные `~/.claude/settings.json` пользователя проверяются в фазе 1b. Нет другого хука — роутер печатает пакет, в лимите строк роутера.
- Секретов, адресов, токенов, содержимого чужих незакоммиченных файлов.
- Bless, записи в репозиторий, изменения claims — пакет только читает.

## Установка

1. `cp <skill>/templates/orient.sh <root>/.claude/scripts/orient.sh`, `chmod +x`; адаптировать блоки 2–4 под канон репозитория (переменные в шапке шаблона).
2. Хук в `<root>/.claude/settings.json` (без matcher):
   ```json
   {"hooks": {"SessionStart": [{"hooks": [{"type": "command",
     "command": "bash \"${CLAUDE_PROJECT_DIR:-.}/.claude/scripts/orient.sh\""}]}]}}
   ```
   Чужой push-доступ к репозиторию → `settings.local.json` (см. `freshness.md`, «Подключение прогона»).
3. Указатель в L0, раздел cold-start: одна строка «стартовый пакет — хук `SessionStart` → `.claude/scripts/orient.sh`». Сам пакет в L0 не описывать.
4. Скрипт — в `sources` документа L0 (`.claude/scripts/*.sh`): переименование или удаление красит L0 в stale.

## Проверка — два шага, оба обязательны

1. Ручной прогон как из хука: `echo '{"source":"startup"}' | CLAUDE_PROJECT_DIR=<root> bash .claude/scripts/orient.sh` → `exit 0`, четыре блока на месте, строки/байты/время в лимите; повторить из подкаталога и без `CLAUDE_PROJECT_DIR`; падение одного блока (нет claims-скрипта, нет doclint) не валит остальные.
2. Живой старт или compact: в контексте виден `SessionStart hook success: ## <заголовок пакета>`. Пока этого не видно — пакет не установлен, в метрику успеха не засчитывать.

## Дрейф

Пакет читает канон по путям и якорям (файл статуса, паттерн строки WIP, claims-команда). Переехал якорь — блок молча пустеет. Поэтому `orient.sh` входит в `sources` L0, а ручной прогон — в проверку каждого `refresh`.
