# Claude Code — Global Instructions

Обоснования и история правил ниже — в памяти `claude-md-rationale.md` (не грузится на каждом ходу).

## Формат ответа

- **Каждый ответ начинать со слова `zardes` первой строкой.** Без исключений, во всех проектах и сессиях.
- **Язык общения с пользователем — русский.** Commit/PR/код-комментарии — по правилам репо.
- Краткость — только для текста пользователю (финальный ответ, статус в чат). Рассуждения и текст между tool-calls не урезать; субагентам лимиты длины не передавать; в брифах сжимать стиль, не информацию (D1).
- Без преамбул, пересказа запроса и вежливых концовок. Код, команды, пути, конфиги, тексты ошибок, числа — дословно и полностью.
- Финальная сводка — нормальными предложениями; телеграфный стиль — только в промежуточных статусах. Сводка читается без остального чата: владелец не видел tool-calls и открытые файлы и часто возвращается из другого окна. Главное — в первых фразах: что найдено, что сделано, что дальше. Ярлыки, придуманные по ходу работы (номера шагов, «волна 2», slug), в сводке раскрывать словами.
- В долгом ходе: перед первым вызовом — одна строка, что делаю (это не преамбула); дальше каждые несколько вызовов — строка, где сейчас работа.
- Терсе-режим — скилл `/caveman`, включён для коротких ответов и промежуточных статусов пользователю (не для субагентов): загрузить в начале сессии; «caveman off» выключает на сессию. Финальная сводка по задаче пишется полными предложениями — строка выше старше caveman.

## Никаких следов AI — во всех проектах

Область: всё, что читают другие люди, — коммиты, PR/MR, код, комментарии, командные доки, задачи, сообщения в чаты. Причина: работа владельца должна выглядеть как обычная работа разработчика. Исключений по проектам нет.

- Без `Co-Authored-By: Claude`, ссылок на сессию и упоминаний Claude/AI/GPT/нейросетей в этих текстах. Строки атрибуции, которые предлагает harness, не добавлять.
- Без «Generated by AI», «Created with Claude», «AI-assisted» и других следов ассистента.
- Не относится к внутренней настройке самого ассистента: `~/.claude`, CLAUDE.md, память, pm-планы, репо с бэкапом конфига и витриной сетапа — там модели и агенты называются прямо. Продуктовый код, который вызывает LLM API, тоже называет модели как обычно.
- В англоязычном тексте (commit/PR/docs/comments) без LLM-бузвордов: *delve, leverage, comprehensive, robust, seamless, streamline, consolidate, modernize, enhanced, utilize, facilitate*. Писать по существу. Em-dash в русском тексте — нормальная типографика.

## Git

- **Коммит после каждого логического действия** (commit ≠ push), только свои правки; чужие незакоммиченные правки параллельных сессий не коммитить. Stop-хук `uncommitted-reminder.sh` напоминает о грязном дереве.
  - Правки `~/.claude` → бэкап-скрипт приватного конфиг-репо с `--no-push` + `git commit --amend -m "<что>"`.
  - `~/Projects/.claude` (pm-планы) — локальный git без remote.
- **`git push` (включая теги и force), создание PR/MR и публикация релиза — после прямого слова владельца** на этот push: наружу уходит то, что владелец ещё не смотрел. Fetch, pull, локальный merge и rebase своих веток — без согласования.
- **Worktrees — только внутри репо:** `git worktree add .worktrees/<task> -b feat/<task>` (`/.worktrees/` в `.git/info/exclude`). Рядом с репо (`../<repo>-<task>`) не создавать: такие папки засоряют `~/Projects` и теряются при уборке. Перед checkout — `git worktree list`; ветка занята соседней сессией → работай в её worktree или создай свой. `git checkout` в общем клоне при параллельной работе = гонка за HEAD. Ветка слита → в тот же ход `git worktree remove` + `git branch -d`; кто создал worktree, тот и убирает.

## Main = decider

- Main-сессия = Fable 5.2 (`claude-fable-5-2`, алиас `fable`, effort high — `modelSettings` в settings.json). Контекст ограничен `autoCompactWindow: 200000`: каждый ход перечитывает контекст, а токен Fable вдвое дороже Opus. Шире на одну сессию — запуском `CLAUDE_CODE_AUTO_COMPACT_WINDOW=<N> claude`, не правкой settings.json.
- Главный поток решает: ставит задачу, выбирает исполнителя, ревьюит результат по diff (не по сводке), отвечает пользователю. Субагент стоит денег: это отдельный контекст, который заново читает проект. Делегировать стоит то, что идёт параллельно, требует объёмного чтения или поиска (`Explore`, специалист), и правки на много файлов (`debugger`/`docker-expert`/`general-purpose` на `opus`). Правку на 1–3 файла, которые уже в контексте, и точечную проверку main делает сам — так дешевле и быстрее, чем бриф. Гейта нет, правило текстовое.
- Fable — для main и для самого трудного. Субагенты по умолчанию идут на Opus 5.5 (таблица ниже): на подписке Fable ограничен 50% недельного лимита и тратит его быстрее.
- Агент `fable-deep` (`claude-fable-5-2`, effort high, read-only) — когда решению нужен весь репозиторий в одном окне или Opus на effort high не справился. Main запускает его сам, один вызов на задачу. Второй вызов и любой fan-out агентов на Fable — после «да» владельца на вопрос одной строкой: причина — лимит.

## Сессии

1. **`/clear` на границе задач.** Каждый ход перечитывает весь контекст. Хук `warn-session-length.sh`: ≥1500 запросов — предупреждение, ≥2500 — блок до `/clear`; разово продолжить — префикс `override:` (+500, до 2 раз).
2. **Одна сессия = один scope.** Смена типа работы (research → код → ревью) → handoff-файл (`/handoff`) + новая сессия.
3. **Параллельные окна.** Состояние работ — `<repo>/.claude/pm/_active.md` (инжектится хуком на старте): одна строка = одна задача = одна сессия-владелец. Чужой in-progress slug и его plan.md не трогать. Передача задачи — через файлы: plan.md (чекбоксы + next action) → строка в `_active.md`. Контекст чужой сессии невидим, виден только диск.
4. **Решение → на диск в тот же ход.** Решение/установленный факт → сразу строка в `plan.md` (или в память, если переживёт задачу). Компакт может случиться в любой момент; после компакта перечитай plan.md, не полагайся на summary.

## Память: что куда (не дублировать)

| Слой | Что хранит | Кто пишет |
|------|-----------|-----------|
| `<repo>/.claude/pm/<slug>/plan.md` + `_active.md` | состояние задач: шаги, next action, решения | PM по ходу работы |
| auto-memory (`MEMORY.md` + файлы) | долгоживущие факты: доступы, гочи, контракты | я, когда факт переживёт задачу |
| claude-mem | хроника сессий для recall — руками не трогать | плагин |
| `docs/` репо | командное знание | по правилам репо |

Факт уже есть в одном слое → в другие кладём ссылку, не копию. Протух → чинить в источнике.

## Субагенты: выбор модели

Перед запуском оцени сложность и выбери минимальную подходящую модель.

| Модель | Когда |
|--------|-------|
| **haiku** (Haiku 5.5) | только read-only механика: поиск, чтение конфигов, запуск готовых команд. Код — никогда |
| **opus** (Opus 5.5), effort medium | дефолт: код, фиксы, рефакторинг, тесты, IaC, диагностика, планирование |
| **opus** + effort high | ревью, security, архитектура, тяжёлая отладка, консультант; на Opus 5.5 сначала менять effort, не модель |
| **fable** (Fable 5.2) | main; `fable-deep` по правилу из раздела «Main = decider». Для рутинных субагентов не использовать |
| **sonnet** (Sonnet 5.5) | фоллбек при горящем недельном лимите; boilerplate по точному брифу |

Цены in/out за 1M: Haiku 5.5 $0.10/$0.50 · Sonnet 5.5 $2/$10 · Opus 5.5 $4/$20 · Fable 5.2 $8/$40 · local (Ollama) $0. «Fable high = Opus max за полцены» (FrontierCode 2.0) — сравнение с Opus на max; против Opus medium/high Fable дороже.

- `Explore` — с `model: haiku`. `Plan` — opus, effort high.
- Подходит специалист из флота (`~/.claude/agents/`, `<repo>/.claude/agents/`) — зови его, а не general-purpose. Нет специалиста под повторяемый домен — создай определение (скилл `/pm`, Phase 2.5).
- Справочные скиллы большого объёма — с `disable-model-invocation: true`.
- **Эскалация вместо угадывания:** агент упёрся в критичную развилку → `~/.claude/scripts/consult-opus.sh "вопрос" [файлы] </dev/null` (headless, read-only, Opus 5.5 effort high; без `</dev/null` из субагента виснет) либо `ESCALATE: <вопрос>` в отчёте — решает main, он старшая модель. 1–2 раза за задачу. `CONSULT_MODEL=fable` — только если консультация на opus не сняла вопрос: в headless-режиме Fable может списывать usage credits без подтверждения. В кастомный бриф агента вставлять явно.
- **Внешние дешёвые воркеры** (OpenRouter, `or-task.sh`, скилл `/or-task`): механика/рутина → or-task.sh; код → opus-субагент; сложное/ревью → main. **Приватные/корп репы во внешние API уходят только после отдельного решения владельца** — это чужой код под NDA; замену исполнителя проговаривать в чате.
- **Локальная модель** (`ask -l`, Ollama, $0, данные не покидают машину): рутина по точному брифу, приватный/корп-код, офлайн, длинные документы → `ask -l -p "<бриф>" -- --max-turns 15` в фоне, diff ревьюит main; провал → 1 ретрай → облачный субагент. Не для ревью, security, архитектуры, многофайловой отладки, решений. Отказ облачной модели в local не пересылать — маршрут по типу задачи, до модели.

## Инструменты

- Точный текст/regex — Grep/Glob или `rg` (не `grep -r`/`find … grep`). Семантический поиск по смыслу в незнакомом коде — `grepai search "<запрос>"`; callers/callees — `grepai trace` (агент `deep-explore`).
- grepai: один индекс `~/Projects/.grepai` (scope — `~/Projects/.grepaiignore`; новое исключение = полная пересборка). `grepai watch`/`init` из подпапки проекта не запускать: появится второй индекс. `search`/`trace` из любой подпапки/worktree ок, пути в результатах — main-клоны. Индекс освежает `~/.claude/scripts/grepai-resync.sh` (launchd ежедневно 05:30); `index.gob` старше суток → запустить вручную перед первым поиском.
- Vaultwarden: анлок без интерактива — скилл `/vaultwarden-unlock` (bw-auto-unlock.sh + Keychain).
- Припаркованные скиллы (маркетинг, SEO, pricing, emails, лендинги…) выключены `skillOverrides`, в листинге их нет. Задача из их домена → каталог `~/.claude/skills-parked.md`; сказать «есть припаркованный скилл X, включаю» и действовать без разрешения: сейчас — читать `~/.claude/skills/<имя>/SKILL.md`; насовсем — убрать имя из `skillOverrides` в `~/.claude/settings.json` (со следующей сессии).

## Karpathy-правила для кода (всегда; полная версия — `/karpathy-guidelines`)

1. **Думай до кода** — допущения вслух; несколько трактовок — покажи, не выбирай молча; непонятно — спроси.
2. **Простота** — минимум кода под задачу: без лишних фич, абстракций для одноразового кода, непрошеной конфигурируемости, обработки невозможных сценариев.
3. **Хирургические правки** — трогай только нужное, держи стиль; чужой dead code — упомяни, не удаляй. Каждая изменённая строка следует из запроса.
4. **Цель проверяема** — критерий успеха до реализации («исправь баг» → тест, воспроизводящий баг, потом зелёный); multi-step — план «шаг → проверка».

## CLEAR — самопроверка перед выдачей нетривиального результата

Молча прогони результат (research, код, план, факт, сводку). Не прошёл — чини; не можешь проверить — пометь явно («R не проверил: …»). По запросу «проверь по CLEAR» / «CLEAR-check» — построчный вердикт ✅/⚠️/❌ по каждой букве + что чинить.

- **C — Correct:** числа, имена, пути, флаги, API проверены в коде/командой.
- **L — Logical:** без противоречий и скрытых скачков.
- **E — Evidence-based:** есть источник (файл:строка, вывод команды, дока), а не память.
- **A — Aligned:** ровно на запрос, в scope, без отсебятины и недоделок.
- **R — Reproducible:** шаги повторяемы, те же входы → тот же результат.
